# LRN-0001 — Propagacao assincrona de tarball no npm (2-5 min) exige smoke npx isolado apos publish

## Context

**Ticket:** TCK-0046
**PRR:** PRR-0044
**Category:** telemetry-insight
**Severity:** low

## Signal That Originated This Learning

Durante a publicação de `@aredes.me/mcp-dadosbr@0.7.0` (`2026-11-23T16:55:17Z`), consultas imediatas `npm view @aredes.me/mcp-dadosbr` ainda retornavam `0.6.0` até a conclusão da fila de processamento assíncrono do registro npm (`16:59:25Z`).

## Cause / Pattern

O registro npm passou a processar tarballs recém-publicados de forma assíncrona (segurança/malware scan), retornando `202`/aviso no CLI antes de atualizar `dist-tags` e o `.tgz` na CDN por 2–5 minutos.

## Impact

Smokes `npx -y` ou verificações P10 rodados imediatamente após `npm publish` podem observar a versão anterior (`0.6.0`) por falso negativo até o flush do packument/CDN.

## Recommendation

Aguardar propagacao de dist-tags e HTTP 200 do .tgz no registry.npmjs.org antes de rodar smoke npx -y em cache limpo

## How to Measure If the Improvement Worked

Execuções futuras de publicação confirmam `version == <alvo>` via `npm view --prefer-online` e download `.tgz` `HTTP 200` antes de disparar o smoke `npx -y` isolado em `/tmp`.
