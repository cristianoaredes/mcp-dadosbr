+# ADR-0001 - Extrair lib/core/lookup.ts para eliminar ciclo core-tools e unificar contrato cnpj_intelligence
+
+## Contexto
+
+Na auditoria arquitetural (`FND-0012` / `TCK-0024`), foram identificadas duas fragilidades estruturais na camada central:
+
+1. **Ciclo de dependência `lib/core/` <-> `lib/tools/`:** `lib/core/intelligence.ts` importava `lookup` de `lib/tools/core.ts`, enquanto `lib/tools/core.ts` importava `executeIntelligence` e `CNPJ_INTELLIGENCE_TOOL` de `lib/core/intelligence.ts` (com import dinâmico e schema duplicado inline). Além de violar a direção de dependência (`tools -> core`), `lib/tools/company.ts` também dependia de `lib/tools/core.ts` apenas para `lookup`.
+2. **Deriva e duplicação do contrato `cnpj_intelligence`:** `lib/tools/core.ts` definia uma cópia própria de `inputSchema` (apenas provider `tavily`, limite `max_queries` divergente) diferente de `CNPJ_INTELLIGENCE_TOOL` em `lib/core/intelligence.ts` (`L458-L525`), e `executeIntelligenceInternal` não normalizava o CNPJ antes de consultar a chave de cache `cnpj:${baseUrl}:${cnpj}`, causando cache miss quando o CNPJ entrava formatado enquanto `lookup()` gravava com dígitos normalizados (ou vice-versa).
+
+## Decisao
+
+1. **Extrair serviço compartilhado em `lib/core/lookup.ts` (`L1-L87`):** mover `PendingRequest`, `getPendingRequestCount()`, `deduplicate()` e `lookup()` para a camada `core`, dependendo apenas de `./http-client.js`, `../config/timeouts.js` e `../types/index.js`.
+2. **Inverter imports para fluxo acíclico:** `lib/core/intelligence.ts:L5` e `lib/tools/company.ts` passam a importar `lookup` diretamente de `core/lookup.js`. `lib/tools/core.ts:L6` importa `{ deduplicate, getPendingRequestCount, lookup }` de `../core/lookup.js` e re-exporta os símbolos (`L103`) apenas para compatibilidade retroativa com testes unitários existentes.
+3. **Fonte única do contrato `cnpj_intelligence`:** `lib/tools/core.ts:L16,L66-L90` importa estaticamente `CNPJ_INTELLIGENCE_TOOL` e `executeIntelligence` de `../core/intelligence.js`, usa `...CNPJ_INTELLIGENCE_TOOL` e `CnpjIntelligenceSchema` de `../core/tool-schemas.js` (`L9,L68`), encaminhando `max_results_per_query ?? max_results` e `max_queries` (`L83-L84`). Em `lib/core/intelligence.ts:L219-L242`, `executeIntelligenceInternal` passa a normalizar `normalizedCnpj = normalizeCnpj(options.cnpj)` antes da leitura de cache e do fallback para `lookup('cnpj', normalizedCnpj, ...)`, e `CNPJ_INTELLIGENCE_TOOL` documenta ambos os provedores `tavily` e `perplexity` (`L471-L475`, `L504`).
+
+## Alternativas descartadas
+
+- **Manter `lookup()` em `lib/tools/core.ts` usando lazy import contínuo:** manteria acoplamento circular bidirecional entre `core` e `tools` e impediria verificação estática limpa do grafo de imports.
+- **Duplicar `lookup()` dentro de `intelligence.ts`:** multiplicaria o mapa `pendingRequests` de deduplicação em voo e reintroduziria inconsistência de TTL/timeout/chaves de cache.
+
+## Consequencias
+
+- **Positivas:** grafo `lib/core/` -> `lib/tools/` estritamente acíclico (nenhum arquivo em `lib/core/` importa de `lib/tools/`), zero duplicação de lógica de deduplicação ou schema de `cnpj_intelligence`, alinhamento de cache hits em CNPJs formatados/não-formatados, garantido em build (`tsc`, `tsconfig.worker.json`) e teste unitário (`test/unit/architecture-hygiene.test.ts`).
+- **Custos / Trade-offs:** `lib/tools/core.ts:L103` mantém re-export de compatibilidade para suites antigas; remoções futuras exigem atualizar esses imports nos testes. Comportamento com Cloudflare KV em produção permanece *a confirmar*.

+# ADR-0002 - Paridade de versao, catalogo de 23 tools e injecao de env vars entre CLI Node e Cloudflare Worker
+
+## Contexto
+
+Na auditoria (`FND-0012` / `TCK-0024`), detectaram-se desvios entre o runtime Node CLI (`package.json` versão `0.6.0`, 23 tools registradas via `lib/tools/index.ts`, configuração por `process.env`) e o runtime Cloudflare Workers (`lib/adapters/cloudflare.ts`, `lib/workers/worker.ts`, `lib/workers/sse.ts`, `lib/workers/openapi.ts`):
+
+1. **Versão divergente (`1.0.0` vs `0.6.0`):** `SERVER.VERSION` em `lib/shared/utils/constants.ts` e literais `"1.0.0"` em `worker.ts`, `sse.ts` e `openapi.ts` divergiam de `package.json` (`"0.6.0"`).
+2. **Catálogo incompleto na rota raiz `/` do Worker:** `worker.ts` listava apenas 5 strings hardcoded no endpoint `GET /`, enquanto `tools/list` (`TOOL_DEFINITIONS`) expõe 23 ferramentas.
+3. **Propagação parcial de secrets no Cloudflare Worker:** apenas `TAVILY_API_KEY` era copiada de `env` para `process.env`, deixando ferramentas OSINT/legais/governamentais no Worker sem acesso a `PERPLEXITY_API_KEY`, `TRANSPARENCIA_API_KEY` e `DATAJUD_API_KEY`. Além disso havia blocos `if (env.TAVILY_API_KEY)` duplicados em `cloudflare.ts` e `worker.ts`.
+
+## Decisao
+
+1. **Fonte única de versão (`0.6.0`):** alinhar `SERVER.VERSION` em `lib/shared/utils/constants.ts:L37` para `'0.6.0'`; `lib/config/index.ts:L13` re-exporta `SERVER_VERSION = SERVER.VERSION`, e `lib/adapters/cloudflare.ts:L163`, `lib/workers/worker.ts:L16,L96`, `lib/workers/sse.ts:L159,L182` e `lib/workers/openapi.ts:L6,L19` consomem `SERVER_VERSION` em vez de strings hardcoded.
+2. **Catálogo dinâmico em `GET /`:** `lib/workers/worker.ts:L17,L109` importa `TOOL_DEFINITIONS` e publica `TOOL_DEFINITIONS.map((tool) => tool.name)` (todas as 23 ferramentas ativas).
+3. **Helper centralizado com allowlist explícita de secrets (`syncWorkerEnv`):** `Env` em `lib/adapters/cloudflare.ts:L34-L37` declara explicitamente `TAVILY_API_KEY`, `PERPLEXITY_API_KEY`, `TRANSPARENCIA_API_KEY` e `DATAJUD_API_KEY`, e `syncWorkerEnv(env)` (`L40-L58`) propaga somente essa allowlist não-vazia para `process.env`, chamado em `cloudflare.ts:L184,L280` e `worker.ts:L166` sem copiar chaves arbitrárias de `env` (como `MCP_API_KEY` ou bindings KV) e sem logar valores.
+
+## Alternativas descartadas
+
+- **Copiar `Object.entries(env)` inteiro para `process.env`:** rejeitada por segurança, pois vazaria segredos de controle (`MCP_API_KEY`) ou tentaria serializar bindings não-string (`KVNamespace`) em `process.env`.
+- **Manter strings hardcoded por arquivo de Worker:** rejeitada pela alta probabilidade de nova deriva entre `package.json`, OpenAPI, SSE e MCP `initialize`.
+
+## Consequencias
+
+- **Positivas:** paridade verificada em testes unitários para versão (`0.6.0`), lista de 23 ferramentas e propagação restrita das 4 API keys de provedores; redução de código duplicado entre `worker.ts` e `cloudflare.ts`.
+- **Custos / Trade-offs:** inclusão futura de uma nova chave de API externa para tools exige adicioná-la intencionalmente em `WORKER_ENV_KEYS` (`lib/adapters/cloudflare.ts:L40-L45`) e `Env`. Execução real no edge Cloudflare Workers (secrets via `wrangler secret put` e comportamento global de isolados) permanece *a confirmar* em ambiente remoto.

+/**
+ * Shared cached & deduplicated lookup service for core entities (CNPJ, CEP).
+ * Extracted into lib/core/ so core modules (intelligence) do not depend on lib/tools/.
+ */
+
+import { httpJson } from "./http-client.js";
+import { TIMEOUTS } from "../config/timeouts.js";
+import { ApiConfig, Cache, LookupResult } from "../types/index.js";
+
+interface PendingRequest {
+  promise: Promise<unknown>;
+  timestamp: number;
+  timeoutId: ReturnType<typeof setTimeout>;
+}
+
+const pendingRequests = new Map<string, PendingRequest>();
+
+export function getPendingRequestCount(): number {
+  return pendingRequests.size;
+}
+
+export async function deduplicate<T>(key: string, fn: () => Promise<T>): Promise<T> {
+  const timeoutMs = TIMEOUTS.DEDUP_TIMEOUT_MS;
+  const existing = pendingRequests.get(key);
+  if (existing) {
+    if (Date.now() - existing.timestamp < timeoutMs) {
+      return existing.promise as Promise<T>;
+    }
+    clearTimeout(existing.timeoutId);
+  }
+
+  const promise = fn();
+  const timeoutId = setTimeout(() => {
+    if (pendingRequests.get(key)?.promise === promise) {
+      pendingRequests.delete(key);
+    }
+  }, timeoutMs);
+  (timeoutId as { unref?: () => void }).unref?.();
+
+  pendingRequests.set(key, {
+    promise,
+    timestamp: Date.now(),
+    timeoutId,
+  });
+
+  try {
+    return await promise;
+  } finally {
+    clearTimeout(timeoutId);
+    if (pendingRequests.get(key)?.promise === promise) {
+      pendingRequests.delete(key);
+    }
+  }
+}
+
+export async function lookup(
+  type: "cnpj" | "cep",
+  input: string,
+  apiConfig: ApiConfig,
+  cache?: Cache
+): Promise<LookupResult> {
+  const baseUrl = type === "cnpj" ? apiConfig.cnpjBaseUrl : apiConfig.cepBaseUrl;
+  const cacheKey = `${type}:${baseUrl}:${input}`;
+  if (cache) {
+    const cached = await cache.get(cacheKey);
+    if (cached) return { ok: true, data: cached };
+  }
+  return await deduplicate(cacheKey, async () => {
+    const result = await httpJson(`${baseUrl}${input}`, apiConfig.authHeaders);
+    if (result.ok && result.data) {
+      const responseData = {
+        ...result.data,
+        source: result.source,
+        fetchedAt: new Date().toISOString(),
+      };
+      if (cache) await cache.set(cacheKey, responseData);
+      return { ok: true, data: responseData };
+    }
+    return {
+      ok: false,
+      error:
+        result.error === "not found"
+          ? `${type.toUpperCase()} not found`
+          : result.error || "unknown error",
+    };
+  });
